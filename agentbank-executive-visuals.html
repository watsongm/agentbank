Exhibit 1 · The stack

When a person's primary tool is an agent, every service sits in the same four-layer stack.

People stop opening apps; they tell an agent what they want. The agent reaches into domain rails — finance, commerce, travel, health — through typed, authenticated interfaces (MCP 1.0, Open Banking v3.1, BIAN v12). Underneath everything is a shared cryptographic trust fabric.

Exhibit 4 · The lifestyle agent

Most consumers end up with one agent across most of life. Every domain plugs into it.

The lifestyle agent is the interface. Around it: the domain rails the person relies on — finance (agentBANK), commerce, travel, health, utilities — all reached through the same kind of typed, consented MCP tool calls.

01 · The channel collapses
Apps stop being where life happens.
They persist for inspection and edge cases, but day-to-day action moves into conversation with the agent.
02 · Products become tools
The unit of value shifts from screens to callable capabilities.
If a capability isn't exposed as a clean MCP / OpenAPI tool, an agent can't reach it — and the customer never sees it.
03 · Consent replaces logins
Permission becomes the new interface primitive.
Scope, expiry, and DPoP sender-constrained rules matter more than passwords and browser sessions.
04 · Audit replaces support
Disputes are resolved by replaying reasoning trails.
What the agent saw, planned, and executed in the hash-chained ledger is the source of truth — for the user, the bank, and the regulator.
05 · Distribution changes
Whoever agents prefer to call wins the relationship.
Banks compete on schema clarity, low-latency deterministic execution, and cryptographic trust — not on app store rankings.
Core idea
One agent, many rails. The consumer's relationship is with the agent; each provider's relationship is with the tool calls the agent chooses to make.
